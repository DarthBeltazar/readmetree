# readmeTreeAutomizer

[![tests](https://github.com/DarthBeltazar/readmetree/actions/workflows/tests.yml/badge.svg)](https://github.com/DarthBeltazar/readmetree/actions/workflows/tests.yml)
[![License: MIT](https://img.shields.io/github/license/DarthBeltazar/readmetree)](LICENSE)
[![Python 3.9+](https://img.shields.io/badge/python-3.9%2B-blue.svg)](pyproject.toml)

*[English version](README.md)*

CLI-инструмент, который сканирует дерево файлов проекта и поддерживает в актуальном
состоянии размеченный блок в стиле `tree` прямо внутри `README.md` — так вы пишете
описание к каждому файлу/папке один раз, а не выравниваете ASCII-дерево руками
каждый раз, когда меняется структура проекта.

## Установка

```
python -m venv .venv
.venv\Scripts\pip install -e . -r requirements.txt
```

## Использование

### Быстрый старт

```
cd ваш-проект
readmetree generate
```

Для обычного случая этого достаточно: сканирует, спрашивает про новое,
записывает/обновляет дерево в `README.md`. Дальше — подробный справочник
по обеим командам и по ситуациям, с которыми реально столкнётесь.

### Команды кратко

| Команда | Алиасы | Что делает |
|---|---|---|
| `readmetree generate` | `gen`, `g` | Полное сканирование → сверка с `.readmetree.yml` → вопросы про новые/изменившиеся пути → обновление `README.md` |
| `readmetree edit <path>` | `e` | Меняет описание одного пути, без полного пересканирования и вопросов про остальное |
| `readmetree remove <path>` | `rm` | Скрывает путь из дерева (`ignore: true`), не трогая файл на диске; `--restore` отменяет |

---

### `readmetree generate`

1. Находит корень проекта (ближайший предок с `.git`, если не передан `--root`).
2. Сканирует дерево файлов, применяя `.gitignore` и фильтр «только отслеживаемое git» (см. [Что попадает в дерево](#что-попадает-в-дерево)).
3. Сверяет скан с `.readmetree.yml`:
   - **новые** пути → спрашивается описание (если не `--check`/`--dry-run`);
   - **пути, исчезнувшие с диска** → описание удаляется из конфига, с предупреждением;
   - **пути, просто скрывшиеся в этом запуске** (стали untracked/`.gitignore`-нутыми/пустой папкой) → описание *сохраняется* на случай, если путь вернётся.
4. Записывает обновлённый `.readmetree.yml`.
5. Рендерит дерево и вставляет его в `README.md` между маркерами `tree:start`/`tree:end` — если маркеров ещё нет, дерево добавляется в конец файла; если самого `README.md` нет, он создаётся.

При запросе описания: **Enter** записывает пустое описание (подходит для
обычной папки вроде `src/` — больше не переспросит); **`?`** пропускает
путь сейчас и переспросит его в следующий раз. **Ctrl+C** сохраняет всё,
что вы успели ответить, и не трогает `README.md`.

#### Флаги

| Флаг | Короткая форма | Значение |
|---|---|---|
| `--dry-run` | `-n` | Показать, что изменится; ничего не писать. Всегда код `0` — для человека, посмотреть глазами. |
| `--check` | `-c` | Неинтерактивно; ничего не писать; код `1`, если реальный запуск что-то изменил бы. Для CI/pre-commit — см. ниже. |
| `--config PATH` | | Файл конфига (по умолчанию: `<root>/.readmetree.yml`) |
| `--readme PATH` | | Файл README (по умолчанию: `<root>/README.md`) |
| `--root PATH` | `-r` | Корень проекта (по умолчанию: ближайший предок с `.git`, иначе cwd) |
| `--verbose` | `-v` | Также печатать, какие пути отфильтрованы и почему |

#### Примеры

```
readmetree generate              # обычный случай
readmetree g -n                  # посмотреть, что изменится, ничего не писать
readmetree gen --root ../другой-проект
readmetree generate -v           # увидеть, что именно отфильтровано и почему
```

### `readmetree edit <path>`

Правит одно описание, не трогая остальное — без пересканирования и вопросов
про другие пути.

```
readmetree edit src/core/Vec3.h
```

`<path>` принимает:
- обычный путь к файлу или папке (завершающий слэш у папки не обязателен — `src/core` и `src/core/` работают одинаково);
- объединённую форму пары для отображения (`src/core/Vec3.h/.cpp`);
- любую из половинок объединённой пары по отдельности (`src/core/Vec3.cpp` найдёт ту же запись, что и `src/core/Vec3.h`).

**Без пути — обзор стрелочками.** `readmetree edit` без аргумента
показывает дерево ровно таким, каким оно попадёт в `README.md` (плюс уже
удалённые пути — в конце списка, помечены «(hidden)»); двигайтесь ↑/↓,
Enter — выбрать строку, дальше выбор действия: **Edit description**,
**Remove from tree** (то же, что `readmetree remove` — ставит `ignore:
true`, описание сохраняется), либо для «(hidden)»-строки — **Restore to
tree**. Каждое действие сохраняется и перерисовывается сразу же, после
чего вы снова на (уже обновлённом) списке — выбирайте следующую строку или
«(done)», чтобы закончить. Если терминал не умеет стрелочные меню
(перенаправленный ввод, некоторые встроенные консоли), на обоих шагах
включается запасной вариант — обычный нумерованный список.

#### Флаги

| Флаг | Короткая форма | Значение |
|---|---|---|
| `--config PATH` | | Файл конфига (по умолчанию: `<root>/.readmetree.yml`) |
| `--readme PATH` | | Файл README (по умолчанию: `<root>/README.md`) |
| `--root PATH` | `-r` | Корень проекта (по умолчанию: ближайший предок с `.git`, иначе cwd) |
| `--force` | `-f` | Редактировать, даже если пути сейчас нет на диске / ещё нет в конфиге |
| `--verbose` | `-v` | Также печатать, какие пути отфильтрованы и почему |

#### Примеры

```
readmetree edit src/render/Camera.h
readmetree e src/render/Camera.h/.cpp   # та же запись, форма пары
readmetree edit --force some/future/path.py   # заранее задать описание
readmetree edit                          # обзор стрелочками, без пути
```

### `readmetree remove <path>`

Для пути, который `generate` продолжал бы показывать (он реальный,
отслеживается git, не в `.gitignore`), а вы просто не хотите его
документировать — это отличается от пути, который реально исчез с диска
(его `generate` и так сам уберёт из конфига). `remove` ставит `ignore:
true` на запись; сам файл не трогается, а описание сохраняется на случай
восстановления.

```
readmetree remove src/core/Vec3.h
readmetree rm src/core/Vec3.h --restore   # вернуть обратно
```

`<path>` принимает те же формы, что и `edit` (обычный путь, папка, любая
половинка объединённой пары). Удаление директории скрывает всё её
поддерево; удаление одной половинки пары заголовок/исходник скрывает обе.
Те же действия «Remove from tree» / «Restore to tree» доступны и из
обзора стрелочками в `readmetree edit` (см. выше) — пользуйтесь тем
входом, каким удобнее.

#### Флаги

| Флаг | Короткая форма | Значение |
|---|---|---|
| `--restore` | `-u` | Отменить предыдущий `remove` — снова показать путь в дереве |
| `--force` | `-f` | Удалить, даже если пути сейчас нет на диске / ещё нет в конфиге |
| `--config PATH` | | Файл конфига (по умолчанию: `<root>/.readmetree.yml`) |
| `--readme PATH` | | Файл README (по умолчанию: `<root>/README.md`) |
| `--root PATH` | `-r` | Корень проекта (по умолчанию: ближайший предок с `.git`, иначе cwd) |
| `--verbose` | `-v` | Также печатать, какие пути отфильтрованы и почему |

#### Примеры

```
readmetree remove build/generated_stub.cpp
readmetree rm build/generated_stub.cpp -u   # восстановить
readmetree remove src/vendor --force        # заранее скрыть путь, которого ещё нет
```

### CI / pre-commit: `--check`

`--dry-run` всегда завершается кодом `0` — он для человека, чтобы посмотреть
глазами, а не для сборки, которая должна упасть при рассинхроне. `readmetree
generate --check` — вариант для CI: неинтерактивный, ничего не пишет на
диск, и завершается кодом `1`, если реальный запуск `generate` изменил бы
`README.md` или `.readmetree.yml` (новые неописанные пути, описание
поправили руками, но не пересобрали, пути добавились/исчезли, ...).

```
readmetree generate --check   # код 0 = актуально, код 1 = устарело
```

Чтобы запускать это автоматически перед каждым коммитом через
[pre-commit](https://pre-commit.com), добавьте в `.pre-commit-config.yaml`
вашего проекта:

```yaml
repos:
  - repo: https://github.com/DarthBeltazar/readmetree
    rev: main  # закрепите на теге, когда он появится
    hooks:
      - id: readmetree-check
```

### Описания хранятся в `.readmetree.yml`

Путь → описание, рядом с вашим проектом. Можно редактировать руками —
обычный YAML. Доступно несколько дополнительных ключей:

- `ignore: true` на записи — скрыть путь, который не покрывает
  `.gitignore`, не удаляя его описание. Обычно руками это не правят:
  `readmetree remove <path>` ставит флаг, а `--restore` его снимает.
- `force_include` — всё равно показать путь из `.gitignore`, одной
  свёрнутой строкой без перечисления содержимого (`collapse: true`, по
  умолчанию) — например, для сгенерированных кадров, которые вы всё же
  хотите задокументировать. `collapse: false` спасает от игнора только
  саму строку пути; его содержимое всё равно останется скрытым, пока не
  получит собственные записи — потому что тот же паттерн `.gitignore`,
  что матчит папку, матчит и всё внутри неё.
- `collapse_siblings` — свернуть группу похоже названных, обычно
  `.gitignore`-нутых директорий (`cmake-build-debug`,
  `cmake-build-release`, ...) в одну строку `cmake-build-*/` с одним общим
  описанием.

Пары заголовок/исходник в одной папке (`Vec3.h` + `Vec3.cpp`, `.hpp`/`.cpp`,
`.h`/`.c`, ...) автоматически объединяются в одну строку дерева
(`Vec3.h/.cpp`) с одним общим описанием — конфиг для этого не нужен.

Переименования не определяются: переименованный путь выглядит как одно
удаление и один новый путь для описания.

### Что попадает в дерево

В git-репозитории в дерево попадают только файлы, которые git реально
отслеживает (застейджены или закоммичены) — новый файл нужно сначала
`git add`, чтобы `readmetree` его увидел. Пути из `.gitignore` и пустые
директории тоже не показываются (`force_include` — способ всё же показать
`.gitignore`-нутый путь, который вы хотите задокументировать). Сам
`.gitignore` никогда не отображается. Вне git-репозитория понятия
«отслеживается» не существует, поэтому применяется только фильтрация по
`.gitignore`.

Если запустить `readmetree` из поддиректории, которая сама не является
корнем репозитория (например, вложенная тестовая фикстура), не передав
`--root`, инструмент поднимется вверх до ближайшего предка с `.git` — а
это может оказаться *другой*, внешний проект. Если выбранный корень не
совпадает с текущей директорией, инструмент сообщит об этом; если это не
то, что нужно — передайте `--root` явно.

## Дерево проекта

Дерево — автогенерируемая часть `readmetree`-блока и живёт только в
[README.md](README.md#readmetreeautomizer) (сама структура и комментарии
к ней — на английском, как и весь код инструмента). Здесь его не дублирую:
копия руками неизбежно рассинхронизируется с реальной структурой при
следующем `readmetree generate`, а этот файл переводится вручную и не
обновляется автоматически.
